# Languages and regions

Reelsaw ships in English and is being made ready for other languages: the work is making translation
possible, not translating. The rules come from the osbytes playbook (`i18n.md`); this page says
where Reelsaw stands and how to work with it.

## In the web app

- **Messages.** Lingui 6 with ICU MessageFormat. Write copy with the macros: `<Trans>…</Trans>` for
  JSX (a link or a styled word inside a sentence stays inside the one `<Trans>`), and
  `const { t } = useLingui()` then `` t`…` `` for strings (titles, errors, props). Plurals and choices
  are `<Plural>` / `plural()`, never a sentence joined from pieces. Imports: `@lingui/react/macro`,
  `@lingui/core/macro`.
- **The catalogue.** `apps/web/src/locales/en.po` is generated from the code and committed. After
  changing copy: `pnpm --filter @reelsaw/web i18n:extract`. CI runs `i18n:check` and fails when the
  catalogue and the code disagree. `@lingui/vite-plugin` compiles catalogues on import; there is no
  compile step.
- **The locale chain** (`apps/web/src/lib/i18n.ts`): `?locale=` (remembered on this browser), the
  locale chosen on this browser, `navigator.languages` matched against the shipped locales, then
  English. `<html lang>` and `dir` follow it.
- **Pseudo-locale.** Open the app with `?locale=en-XA`: translated text shows accented and longer, so
  a string that is still English was not wrapped, and a clipped label will clip in German too.
  `?locale=en` switches back. Check a UI change in it before calling it done.
- **Layout.** Logical Tailwind classes only: `ms-`/`me-`, `ps-`/`pe-`, `start-`/`end-`, `text-start`,
  `border-s`, `rounded-s`. Physical ones (`ml-`, `pr-`, `left-`, `text-right`) fail the ratchet.

## The ratchet

`scripts/i18n-literals.mjs` counts, in `apps/web/src`, JSX text outside the macros
(`i18n/jsx-text`), `aria-label` / `title` / `placeholder` / `alt` / `label` props given a literal
(`i18n/string-props`), and physical CSS classes (`i18n/physical-css`). The counts are in
`scripts/lint-baseline.json` with the lint rules: a change may lower them, never raise them, and
the baseline is lowered in the change that wrapped the strings (`node scripts/lint-ratchet.mjs
--update`). `node scripts/i18n-literals.mjs --list` lists every site.

## Not done yet

In the order they are planned, each its own change:

1. Wrap the remaining web screens, one area per change (the ratchet shows what is left).
2. Formatting through one `Intl` module that takes the active locale: `packages/shared/src/format.ts`
   formats counts, sizes and days today, some of it pinned to English; money as minor units plus a
   currency code.
3. Locale and time zone on the account, so emails, notices and jobs render for the recipient; the
   account setting joins the locale chain.
4. Server-side messages: errors carry a stable code and parameters, and the sentence is rendered
   from a catalogue in the requester's locale (tRPC errors, notices shared through `@reelsaw/shared`,
   emails, MCP result sentences, CLI messages for people).
5. The website (`website/`), with the same catalogue format.

Staying English, because they are contracts or for operators: log lines, config keys and `.env`
names, API fields, MCP tool names and descriptions, CLI commands and flags, `--json` output, metric
and event names.

## Adding a language

A language is added when someone asks for it: translations arrive as pull requests to
`apps/web/src/locales/<locale>.po` (CLA and DCO apply), the locale joins `lingui.config.ts` and
`SHIPPED_LOCALES`, and a missing message falls back to English. A right-to-left language gets a
full pass of the main flows with `dir="rtl"` before it is listed.
