# Languages and regions

Reelsaw ships in English and is ready for other languages: every string a person reads, in the web app, the
server's errors, notices, emails, MCP results and CLI lines, and on reelsaw.com, comes from a message catalogue,
and every number, size, amount and date is formatted for the reader's locale. Adding a language is translating
catalogues, not changing code. The rules come from the osbytes playbook (`i18n.md`); this page says how Reelsaw
applies them.

## Locales

`packages/shared/src/locale.ts` holds the one list: `SHIPPED_LOCALES` (today `en`) and the pseudo-locale `en-XA`,
with `matchLocale` (a browser or Accept-Language tag, matched exactly or on its primary subtag) and `localeDir`.
The web app, the server and the account setting all read it, so a locale ships everywhere at once.

**The account setting.** Settings → Account → Language and region stores a locale (or "follow the browser") and an
IANA time zone on the account (`user.locale`, `user.time_zone`). The same service backs tRPC
`me.localePrefs` / `me.updateLocalePrefs`, MCP `get_locale_preferences` / `set_locale_preferences` and
`reelsaw locale-prefs <email> [--locale <code>|follow] [--time-zone <zone>|utc]` (`apps/server/src/notify/locale.ts`).

## In the web app

- **Messages.** Lingui 6 with ICU MessageFormat. Write copy with the macros: `<Trans>…</Trans>` for
  JSX (a link or a styled word inside a sentence stays inside the one `<Trans>`), and
  `const { t } = useLingui()` then `` t`…` `` for strings (titles, errors, props). Plurals and choices
  are `<Plural>` / `plural()`, never a sentence joined from pieces. Imports: `@lingui/react/macro`,
  `@lingui/core/macro`. Labels in module-level constants are `msg` descriptors, rendered at use.
- **The catalogue.** `apps/web/src/locales/en.po` is generated from the code and committed. After
  changing copy: `pnpm --filter @reelsaw/web i18n:extract`. CI runs `i18n:check` and fails when the
  catalogue and the code disagree. `@lingui/vite-plugin` compiles catalogues on import; there is no
  compile step.
- **The locale chain** (`apps/web/src/lib/i18n.ts`): `?locale=` (remembered on this browser), the account's
  choice (once signed in), the locale chosen on this browser, `navigator.languages` matched against the shipped
  locales, then English. `<html lang>` and `dir` follow it, and every API call sends it as `x-reelsaw-locale`, so
  errors and notices come back in the same language.
- **Pseudo-locale.** Open the app with `?locale=en-XA`: translated text shows accented and longer, so
  a string that is still English was not wrapped, and a clipped label will clip in German too.
  `?locale=en` switches back. Check a UI change in it before calling it done.
- **Layout.** Logical Tailwind classes only: `ms-`/`me-`, `ps-`/`pe-`, `start-`/`end-`, `text-start`,
  `border-s`, `rounded-s`. Physical ones (`ml-`, `pr-`, `left-`, `text-right`) fail the ratchet.

## Formatting

`packages/shared/src/format.ts` is the one `Intl` module: `formatNumber`, `formatPercent`, `formatBytes`,
`formatMb`, `formatSeconds`, `formatDay`, `formatDateTime`, `formatRelative`, `formatList` and `formatMoney`.
Each formats for the active locale (`setFormatLocale`: the Lingui locale in the web app, the request's or the
recipient's on the server); an explicit `locale` wins. Money is minor units plus an ISO 4217 code
(`formatMoney(1900, "USD")` → "$19"), never a float of dollars. Days take `timeZone` (the recipient's in mail) or
`utc` (a billing period, the same day for everyone). Unit symbols (B, MB, s, min, h) stay as they are; the number
around them is localised. `plural()` from `@reelsaw/shared` is English-only, for text that stays English; text a
person reads uses an ICU plural.

## On the server

`apps/server/src/i18n.ts`. Copy is written with Lingui's runtime `msg` (`@lingui/core/runtime-macro`, imported
directly in each file, since the extractor reads only that import; no build step):

```ts
msg`Project ${{ title }} is ready`                                       // a sentence (hash id)
msg({ id: "project.not_found", message: msg`No project ${{ id }}` })       // an error: the id is a stable code
msg({ id: "clips.ready", message: plural({ n }, { one: "# clip is ready", other: "# clips are ready" }) })
```

- **Errors** are `new AppError(code, msg({ id, message }))`: the sentence is rendered in the requester's
  locale, and tRPC sends `data.messageId` and `data.params` beside it, so a client can render its own copy.
  QuotaError carries its code the same way. MCP and the CLI show the sentence.
- **The locale of a request**: the web app's `x-reelsaw-locale` header, else the account's setting, else
  Accept-Language, else English (`localeMiddleware`, `scopeAccount`). The account's time zone comes along.
- **Mail, notices and jobs** render for the recipient, not the actor: `inLocaleOf(user, () => …)`. `<html lang dir>`
  in mail follows it.
- **The CLI** takes `REELSAW_LOCALE`, else `LANG`.
- **The catalogue** is `apps/server/assets/locales/<locale>.po` (in `assets/`, so the image ships it). After
  changing copy: `pnpm --filter @reelsaw/server i18n:extract`; CI runs `i18n:check`. A message missing from a
  locale falls back to the English in the code.

Staying English, because they are contracts or for operators: log lines, config keys and `.env`
names, API fields, MCP tool names, titles and descriptions, CLI commands, flags and usage synopses, `--json`
output, metric and event names, and what is stored as it happened: failure reasons and the activity feed's events (written once, in
English, for the operator and the issue report).

## The website

reelsaw.com (`website/`) uses the same catalogue format: Lingui's runtime `msg` and `t()` from
`website/lib/i18n.ts` (`rich()` for a sentence with a link inside), catalogues in `website/locales/<locale>.po`.
A build is one language, chosen by `SITE_LOCALE` at build time (default `en`; `SITE_LOCALE=en-XA` builds the
pseudo-locale). `pnpm i18n:extract` in `website/` after changing copy; CI's `site` job runs `i18n:check`.

## The ratchet

`scripts/i18n-literals.mjs` counts what bypasses the catalogue: in `apps/web/src`, JSX text outside the macros
(`i18n/jsx-text`), `aria-label` / `title` / `placeholder` / `alt` / `label` props given a literal
(`i18n/string-props`) and physical CSS classes (`i18n/physical-css`); in `apps/server/src`, a `TRPCError` or
`QuotaError` given a literal sentence instead of an `AppError` (`i18n/server-errors`); on the website, JSX text
(`i18n/site-text`). The counts are in `scripts/lint-baseline.json` with the lint rules: a change may lower them,
never raise them, and the baseline is lowered in the change that wrapped the strings
(`node scripts/lint-ratchet.mjs --update`). `node scripts/i18n-literals.mjs --list` lists every site.

## Adding a language

A language is added when someone asks for it: translations arrive as pull requests to
`apps/web/src/locales/<locale>.po`, `apps/server/assets/locales/<locale>.po` and `website/locales/<locale>.po`
(CLA and DCO apply); the locale joins `SHIPPED_LOCALES` and the three `lingui.config.ts`, and a missing message
falls back to English. A right-to-left language gets a full pass of the main flows with `dir="rtl"` before it is
listed.
